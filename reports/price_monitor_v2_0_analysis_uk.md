# Комплексний аналітичний звіт
## Автоматизоване ринкове ціноутворення, верифікація номенклатурних позицій та аудит закупівель
**Основа:** масив `PRICE2026` та методологія `Price Monitor v2.0`.

## 1) Архітектура автоматизованої системи (Agentic Architecture)
Система реалізована як набір спеціалізованих агентів з чітким розподілом відповідальності:
- **Coordinator Agent**: оркестрація пайплайна, маршрутизація задач, аудит етапів.
- **Fetch Browser Agent**: збір ринкових пропозицій і метаданих із веб-джерел.
- **Normalization Agent**: уніфікація UOM, очищення назв, нормалізація валюти/ПДВ.
- **SpecMatcher**: семантико-технічна перевірка відповідності ТЗ.
- **Pricing Engine**: розрахунок `expected_prices` методом **weighted median**.
- **ADS (Anomaly Detection Skill)**: п’ятишарова детекція аномалій і ризик-сигналів.

## 2) Алгоритмічні засади перевірки
### 2.1 SpecMatcher: строгі статуси відповідності
Кожна пропозиція отримує один із статусів:
- `MATCH`
- `NEAR_MATCH`
- `MISMATCH`

Критична невідповідність (наприклад, інший матеріал або діаметр) маркується як:
- `MISMATCH + critical=True`
- `is_valid=False`
- подальша обробка позиції блокується.

### 2.2 ADS v2.0: п’ять шарів захисту
- **L1 (Bounds):** ціна `< 1 грн` або `> 10 млн грн` → `REJECT`.
- **L2 (Flash Crash):** різкий стрибок/обвал проти останньої валідної ціни → `QUARANTINE`.
- **L3 (Z-Score):** статистичний викид (порогове правило) → `QUARANTINE` або `REJECT`.
- **L4 (CUSUM):** зсув середнього/режиму ринку → `WARNING: REGIME_SHIFT`.
- **L5 (Peer Consensus):** відхилення від групової медіани понад поріг → `QUARANTINE`.

### 2.3 Pricing Engine
Фінальна очікувана ціна формується не середнім, а **зваженою медіаною**:
- ваги = `confidence_score`
- невалідні та критично невідповідні оферти виключаються до агрегації.

## 3) Узагальнений ринковий аналіз за групами
### 3.1 Санітарно-технічна арматура (згони латунні/нікельовані)
- Виявлено значну волатильність для латунних згонів 1 1/2".
- Верхні цінові екстремуми відхиляються від медіани настільки, що потребують `L3/L5`-маркування та перевірки в `Analyst Review Queue`.
- Для нікельованих згонів 3/4" ринок суттєво стабільніший, що дозволяє автоматичну валідацію без ручного втручання.

### 3.2 Запобіжна арматура (компенсатори гідроударів)
- По валідних пропозиціях зафіксований майже «плоский» ціновий профіль.
- Дешеві аналоги з відхиленням характеристик повинні блокуватися через `MISMATCH (critical)`.

### 3.3 Промислова запірна арматура (затвори/засувки)
- У великих діаметрах ключовий ризик — **підміна матеріалу або DN/PN**.
- Приклади невідповідності (інший диск/інший діаметр) не мають потрапляти в `expected_prices`.

### 3.4 Кульові крани (муфтова арматура)
- Часті причини браку: тип ручки (важіль vs метелик), тип різьби (ВВ vs ВЗ).
- Валідні оферти формують реалістичний коридор, а невідповідні — відсікаються SpecMatcher.

### 3.5 Полімерні трубопроводи (PPR-фітинги)
- Преміум-бренди можуть мати кратний розрив від бюджетного сегмента.
- Такі розриви коректно обробляються через `L3/L5` з обов’язковою ручною перевіркою аномальних точок.

## 4) Аудит і доказовість
### 4.1 Analyst Feedback Loop
- Черга `GET /api/v1/review/queue` для ручного розгляду `QUARANTINE`.
- Рішення аналітика (`ACCEPT`/`REJECT`) зберігаються в `ads_feedback`.
- Цикл зворотного зв’язку використовується для калібрування порогів ADS.

### 4.2 Незмінна доказова база
- Для MHTML/джерел зберігається `SHA-256` у `content_hash`.
- Це формує юридично значущий audit trail та контроль цілісності.

### 4.3 B2B vs B2G порівняння
- Регулярний розрахунок `spread_signal` на базі `retail_b2b_median` vs `prozorro_median`.
- Результат використовується для формування переговорного пакета (Negotiation Pack).

## 5) Висновки
1. Архітектура Price Monitor v2.0 придатна до автоматизованого очищення ринкових даних від технічних та статистичних шумів.
2. Комбінація `SpecMatcher + ADS` істотно знижує ризик помилкової закупівельної бази.
3. `Weighted median` забезпечує стабільні `expected_prices` в умовах волатильності.
4. Контур доказовості (`SHA-256`, review queue, feedback) підтримує вимоги аудиту й комплаєнсу.
